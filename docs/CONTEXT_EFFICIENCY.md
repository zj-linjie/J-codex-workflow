# 上下文效率改动与验证

2026-10-14。对应 [#4 状态返回与读取](https://github.com/zj-linjie/J-codex-workflow/issues/4) 和 [#5 技能交接与按需验收](https://github.com/zj-linjie/J-codex-workflow/issues/5)。这是本地实现验证记录，未完成真实 Codex 宿主用量对照。

## 实现

- MCP 返回 run 的工具支持可选 `view=compact|full`，缺省 full 兼容旧客户端。compact 保留运行版本、任务身份/状态与就绪任务，省略长计划、结果和事件；完整数据仍持久保存。字段以 `CONTRACT.md` 为准。
- 新版技能正常调用使用 compact，成功写入后复用返回状态。冲突、不确定或外部变化时重新对账；缺少计划、历史或验收证据时读取 full。看板用 compact 绑定运行 ID 后继续自行读取完整状态，无需改 HTML/CSP。
- 子代理使用限定范围的证据简报和简短结果交接；主代理逐项验收实际产物。在草案阶段按用户要求、复杂度和风险选择独立复核；已确认要求保留。
- 异常恢复移至明确触发的参考文件，Skill 正文从 8,141 降至 6,360 字节，减少约 21.9%。全部技能与参考合计由 19,059 增至 19,626 字节；这里降低的是通常加载的正文，不宣称所有分支同时加载时也减少。

## 载荷对照

复现：`python3 scripts/measure_payloads.py`。脚本只使用临时数据库，创建 10 项 primary 合成任务，每项经历 running/submitted/done；包含固定长度的角色说明、标准、摘要和验收文字。不启动代理、不调用模型、不读取用户数据库。

对照同一已提交状态：旧路径返回一次 full 写入结果并读取一次 full；新路径只返回一次 compact 写入结果。统计 JSON UTF-8 回复字节，包括 text 与 structuredContent，不包含请求参数、工具定义、模型推理或聊天上下文重放。

| 指标 | 旧路径 | 新路径 |
| --- | ---: | ---: |
| 任务状态写入 | 30 | 30 |
| 协调返回次数 | 60 | 30 |
| 协调回复字节 | 1,234,924 | 33,617 |
| 最后一次完整/精简回复字节 | 34,078 | 1,085 |

该样例累计回复载荷减少 97.28%。收益依赖任务数与长字段长度，不能换算成真实 token、费用或全部任务的固定节省比例。新增 view 字段也会增加少量工具定义文本。页面轮询仍为本地 MCP 调用，不发起模型请求。
